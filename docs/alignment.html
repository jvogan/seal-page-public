Sequence alignment

This guide includes source and direct-edition features. Check the edition comparison for the first Store release. Screenshots and recordings show the direct edition. Compare editions.

Align two or more sequences with a selectable engine. Run an alignment from the CLI, call it over MCP, or read it in the desktop viewer. The same engine IDs are exposed in the desktop viewer and over MCP.

Pairwise alignment

Align two sequences by passing both to seal align. Each sequence is a positional argument (raw text, a file path, or a library name).

seal align ATGCGT ATGCAT

The same command takes files, so a pairwise alignment of two saved sequences looks like this:

seal align seq1.fa seq2.fa --json

Alignment lines the sequences up, inserting gaps to show where they correspond. To compare two sequences base by base instead, with mismatches, insertions, and deletions reported as a diff, use seal diff (see Sequence diff).

Multiple sequence alignment (MSA)

Pass three or more sequences to align them as a multiple sequence alignment. seal align accepts 2 to 10 sequences in one call.

Open Alignments and click Load examples to add six synthetic examples with saved results:

  • A 1,200 bp Sanger template with two primers and overlapping AB1 reads.
  • A 2.4 kb clone with six primers and overlapping AB1 reads.
  • A 1,200 bp DNA reference and an 11-sample variant panel.
  • Three DNA sequences covering 2.4 kb, with substitutions and an insertion.
  • Three 420-residue protein sequences with substitutions and a deletion.
  • A 900 nt RNA reference and five variants with partial coverage.

The saved results use MUSCLE 5.3 or Clustal Omega 1.2.4. Open a result to inspect it, or choose Download example inputs for its FASTA files and, for trace examples, AB1 files and primer sequences. Loading examples preserves saved alignments and source edits. All example sequences, signals, and quality scores are project-authored synthetic fixtures.

seal align seq1.fa seq2.fa seq3.fa

The result is a compact multiple sequence alignment. Add --json for machine-readable output. The CLI always runs the local SEAL progressive algorithm; engine selection lives in the desktop viewer and over MCP, covered next.

Alignment engines

The CLI align command always runs the local SEAL progressive algorithm and has no engine flag. The desktop viewer and MCP expose three engine IDs: SEAL progressive (the default), MUSCLE, and Clustal Omega.

seal align seq1.fa seq2.fa seq3.fa --format fasta
FlagDefaultDescription
--format <fmt>clustalOutput format: clustal or fasta.
--jsonfalseEmit structured JSON output.
--save <path>noneWrite the rendered output to a file path.

MUSCLE and Clustal Omega run from a validated local binary. The desktop app and the Node development CLI and MCP server look for one, and Settings offers a guided Homebrew install if none is present. When the binary is missing, the request returns an engine_unavailable result naming the engine, so an alignment is always attributable to the engine that produced it. The Rust seal CLI runs the built-in engine only.

The viewer

The desktop MSA viewer shows the alignment across the available window width. It carries a method and emphasis control strip so you can switch the engine and change what the alignment emphasizes without leaving the view.

When some sequences are skipped, the viewer uses a compact skipped-sequence disclosure rather than a stack of warning cards, so a wide alignment stays readable and the skipped entries stay one click away.

Displayed identity reserves 100% for exact agreement. A real mismatch cannot round up to 100%, ambiguous-only columns do not count as exact conservation, and trace-backed review separates high-quality mismatches from calls without enough quality evidence. If a rerun fails, the last valid result remains visible with the new error instead of disappearing.

Over MCP

Alignment is available to agents over MCP with the engine IDs seal-progressive, muscle, and clustal-omega. A request for muscle or clustal-omega runs the local binary when one is installed and returns engine_unavailable when it is not. See the MCP tool reference.
