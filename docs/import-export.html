Import and export

Read eleven formats, write FASTA, GenBank, and GFF3. Bring sequences into your workspace by file, paste, or drag, and write them back out from the CLI or the desktop app.

Supported formats

SEAL reads and writes three sequence formats. The parser detects the format from the file contents, so you do not pass a format flag on import.

FormatReadWriteCarries features
FASTAYesYesNo
GenBank (.gb, .gp, .gbff)YesYesYes
GFF3 (.gff, .gff3, .gtf)Yes (parser round-trips)YesYes

Auto-detection keys off the file contents: a FASTA > header, a GenBank LOCUS line, or a GFF3 ##gff-version 3 directive. A file with multiple > headers or multiple LOCUS blocks is a multi-record file, and import splits it into one block per record.

FASTA records hold sequence only. To preserve features, names, and topology in a round trip, use GenBank or GFF3.

More formats you can import

Beyond the three formats above, the desktop app reads several more formats and detects each one from the file contents. These are import only. To write a sequence back out, export it as FASTA, GenBank, or GFF3.

FormatDetected fromImports as
FASTQ@id, sequence, +, and quality linesOne DNA block per read, with Phred quality
EMBL / ENAAn ID line with a BP length tokenDNA block with features
SBOLRDF/XML or JSON component definitionsDNA or protein block
PDB / mmCIF (.pdb, .cif, .ent, .mmcif)SEQRES, ATOM, or _entity_poly recordsOne block per chain
Binary annotated DNA (.dna)The binary .dna file you uploadDNA block with features
ABI (.ab1, .abi)The binary chromatogram file you uploadDNA block with quality
CSVA delimited header row, file upload onlyOne block per row
Structured sequence JSONA supported annotated-sequence object or arrayDNA block with annotations

Detection keys off the content, so you do not pass a format flag. Upload .dna and .ab1 as files; their data is binary and cannot be pasted as text. CSV imports by file upload.

Import

Use seal import to read one or more FASTA or GenBank files, supported sequence directories, or recognized structured workspace exports into the shared workspace. Multi-record files are split into separate blocks automatically. Recognized inventory database layouts are detected as structured exports.

seal import plasmid.gb
seal import primers.fa vector.gb insert.fa
seal import seqs.fa --conversation-id conv-abc123

Pass --dry-run to parse and report records without writing any blocks. This is the safe way to inspect a large directory before committing to it.

seal import /path/to/workspace-export --recursive --dry-run --format text

Flags

Paste or drag in the desktop app

You do not need a file to start. In the desktop app, paste raw sequence or FASTA, GenBank, EMBL, FASTQ, GFF3, SBOL, PDB/mmCIF, or supported annotated-sequence JSON text into the intake field, or drag a sequence file onto the window. CSV is recognized on paste but routes you to the file picker. The same parser runs, so format detection and multi-record splitting behave the same as the CLI. SEAL adds the new blocks to the active Entry.

To fetch a record straight from NCBI instead of importing a local file, see Sequence sources and the seal fetch command in the CLI reference.

Export

Use seal export to write blocks from the shared workspace. The subcommand selects the format: a CSV summary, a Markdown document, a slide-friendly Markdown summary, GenBank, or a full JSON dump.

SubcommandDescription
csvCSV summary table, one row per block.
markdownMarkdown document, one section per block.
slide-summaryCompact slide-friendly Markdown, one bullet per block.
genbankGenBank export for one block, all blocks, or one file per block.
workspace-jsonFull JSON dump of every block in the scratch workspace.

Every subcommand accepts --output <path> to write a file instead of printing to stdout. When you write to a file, the command returns a small JSON envelope with the format, the block count, and the path.

seal export csv --include-features --output report.csv
seal export markdown --include-analysis --output summary.md
seal export workspace-json --output workspace.json

GenBank export

The genbank subcommand writes GenBank flat files, which preserve features and topology. Export one block, every block into a single multi-record file, or one .gb file per block.

seal export genbank --output all-blocks.gb
seal export genbank --block block-abc --output plasmid.gb
seal export genbank --output-dir genbank-export
FlagDefaultDescription
--block <id>noneExport only one block; omit to export all blocks.
--output <path>noneWrite a single GenBank file, possibly multi-record.
--output-dir <dir>noneWrite one .gb file per exported block.

The desktop app shows the same GenBank flat file in a read-only export view before you save it, so you can confirm the record and its features.

To convert a single sequence between formats without going through the workspace, use seal convert myseq.gb --to fasta. See CLI reference.

Native Save As in the desktop app

The desktop app saves through a native Save As dialog, so you choose the destination with the system file picker. The path you pick is recorded with the export, which means the most recent file you wrote shows up under Reveal Latest Export. Use that to open the saved file in Finder right after a save, without retracing the path by hand.

GFF3

SEAL writes spec-compliant GFF3. Every file starts with the ##gff-version 3 directive, and the parser round-trips its own output.

A feature whose location is split into several segments, such as a multi-exon CDS, is written as joined features: the segments share one ID=, and each segment carries a Parent= pointing at that shared id. This keeps a joined feature intact across an export and re-import.

##gff-version 3
chr1  SEAL  CDS  100  300  .  +  0  ID=cds1;Parent=gene1
chr1  SEAL  CDS  450  600  .  +  0  ID=cds1;Parent=gene1

The two rows above share ID=cds1, so they describe the two segments of one joined CDS rather than two separate features.

For the exact JSON shapes that import and export emit across the CLI, MCP, and the app, see the IO contract.
