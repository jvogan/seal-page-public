Terminal dock

This guide covers source and direct-edition tools. These tools are not bundled with the first Store release. Compare editions.

The terminal dock is a center-pane terminal in the SEAL desktop app. Launch a local agent CLI from inside the app, with the workspace agent context pinned to the shell.

What the dock is

Electron builds expose a terminal in the center pane that launches a pinned shell. On macOS and Unix it prefers a PTY-backed bridge, so interactive CLIs that expect a real terminal behave normally. The dock is one pinned shell, not a row of per-agent tabs.

The terminal runs on the same machine as the desktop app, so anything you start in it can use the same on-device workspace. A CLI or MCP agent launched here writes to SQLite, and Activity records the change. See the agent control plane for setup.

The terminal dock is desktop-only. Browser builds show a quiet desktop-only terminal state instead of a live shell. See Desktop-only behavior below.

Pinned context

When the dock starts a session, it pins the SEAL agent context so a fresh agent has the same starting point you would give it by hand:

  • AGENTS.md, the repository rules and high-risk files.
  • docs/AI_AGENT_PLAYBOOK.md, instructions for an agent starting without thread history.
  • npm run agent:doctor, the read-only readiness check.

Run the doctor first in any new session. It reports repository state, release configuration, live development ports, core scripts, and key documentation.

npm run agent:doctor

Launch an agent

From the pinned shell, start whichever CLI you use. The dock supports Codex, Claude, Gemini, Grok, or any other local CLI on your machine. The terminal does not wrap or replace these tools; it gives them a shell with the workspace context already pinned.

# start an agent CLI in the pinned shell
codex
claude
gemini

To make an MCP agent's writes share the file the running app reads, set SEAL_DB_PATH before you launch it. See MCP setup for the path and config, and the agent control plane for how the shared workspace fits together.

Session lifecycle

The dock owns the sessions it starts. When the dock or the app closes, SEAL kills the attached sessions rather than leaving orphaned processes behind. Treat a dock session as scoped to the app window: close the window and the shell it launched goes with it.

Desktop-only behavior

The terminal dock needs the Electron shell. In other build and runtime states, the dock reports a clear status instead of a fake terminal:

RuntimeWhat the dock shows
Browser buildA quiet desktop-only terminal state. It does not print the pinned agent prompt as fake scrollback.
Electron, missing terminal preloadA reload-needed state.
Electron, stale main processA SEAL-restart state instead of raw IPC errors.

The pinned intro is reserved for real Electron terminal sessions. To use the dock, run the desktop build. See Install SEAL.
