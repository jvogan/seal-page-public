Codon optimizers

Screenshots and recordings show the direct edition. Compare editions.

Optimize existing coding sequences with pluggable host profiles. A small registry separates the host codon usage table, genetic code, and synonymous-codon strategy. If your starting point is a protein, first create a clearly labelled nucleotide draft with reverse translation.

Optimize a coding sequence

Run seal optimize to codon-optimize a DNA sequence for a target host. Pass a sequence inline, or pipe one in.

seal optimize ATGAGCAAAGGCGAAGAACTG --organism ecoli

Set the reading frame with --frame and report the Codon Adaptation Index of the result with --cai. The optimizer profile (--optimizer) and a non-standard genetic code (--table) are available through the TypeScript CLI and the desktop app.

npm run dev:cli -- optimize myseq.fa --organism bsubtilis --optimizer balanced_usage --cai

The command flags:

FlagTypeDescription
--organismstringTarget host. Default ecoli. The shipped CLI accepts ecoli, human, and yeast; the desktop app and TypeScript CLI accept all seven host profiles.
--optimizerstringOptimizer profile id. Default max_frequency. Available through the TypeScript CLI and the desktop app.
--framenumberReading-frame offset: 0, 1, or 2. Default 0.
--tablenumberNCBI translation table: 1, 2, 5, 11, 13, or 22. Available through the TypeScript CLI and the desktop app.
--caiflagCalculate the Codon Adaptation Index after optimization.
--jsonflagOutput as JSON.
--savestringSave the result to the library, optionally with a name.

Use --table when the sequence is read under a non-standard genetic code, such as a mitochondrial table, so the optimizer preserves the correct protein. The reading frame and any bases before it are left unchanged.

Codon optimization also runs in the desktop app from the codon optimize dialog, against the same registry. See Codon analysis for usage tables, GC content, and host comparison.

Host profiles

A host profile is the codon usage table the optimizer matches against. SEAL ships seven built-in hosts:

IdHost
ecoliE. coli
humanHuman
yeastYeast
pichiaPichia pastoris
sf9Sf9 insect
choCHO mammalian
bsubtilisB. subtilis

The host table supplies the codon frequencies. The genetic code is separate: it is the NCBI translation table used to read the input and to preserve protein identity in the output.

The optimizer registry

Optimization is routed through one registry that separates three concerns:

  • Codon usage table: host frequency data.
  • Genetic code: the NCBI translation table used to preserve protein identity.
  • Optimizer profile: the strategy that chooses synonymous codons.

Three optimizer profiles are built in:

IdStrategy
max_frequencyAlways picks the highest-frequency synonymous codon for each amino acid. This is the legacy SEAL behavior and the default.
balanced_usageAllocates synonymous codons so each amino acid approximates the target host codon distribution across the sequence, instead of always picking the top codon.
synthesis_guardedScores host preference while avoiding rare codons, local GC extremes, homopolymers, common cloning sites, and simple internal expression motifs when possible.

The guarded profile is a lightweight local screen, not a replacement for vendor synthesis review. Every optimizer result remains a computational design draft until independently checked.

The plugin API

You can register your own optimizer. Call registerCodonOptimizer before the codon optimize dialog is rendered. App-level imports, extension entry points, and test setup files are good places to do that. Built-in optimizer ids cannot be replaced. Re-registering the same custom id updates that module, which is useful during development or hot reloads. category is optional for custom registrations and defaults to custom.

import {
  getSynonymousCodonCandidates,
  registerCodonOptimizer,
  rewriteSynonymousCodons,
} from '../src/bio/codon-optimizers';

registerCodonOptimizer({
  id: 'my_optimizer',
  label: 'My optimizer',
  shortLabel: 'Mine',
  description: 'Chooses synonymous codons with a lab-specific policy.',
  provenance: 'Lab internal profile v1',
  optimize: (context) => {
    // context.input: original sequence
    // context.upper: DNA-normalized sequence
    // context.usage: selected host codon usage table
    // context.translationTable: effective NCBI genetic code
    // context.frame: reading-frame offset
    // context.options: optimizer options
    return rewriteSynonymousCodons(context, (aa, currentCodon) => {
      const candidates = getSynonymousCodonCandidates(
        aa,
        context.usage,
        context.translationTable,
      );
      return candidates[0]?.codon ?? currentCodon;
    });
  },
});

The optimize function receives a context with the original and DNA-normalized sequence, the selected host usage table, the effective NCBI genetic code, the reading-frame offset, and the optimizer options. Use rewriteSynonymousCodons to walk the coding sequence codon by codon and getSynonymousCodonCandidates to read the host's synonymous codons for an amino acid.

Custom optimizers must preserve sequence length and protein identity. Read codons through context.translationTable.codons[codon] rather than a hard-coded standard code, so mitochondrial and other non-standard codes stay correct.

Wrapping an external tool

For an external tool such as DNA Chisel, CodonTransformer, or a lab service, keep the adapter at the registry boundary: convert the SEAL context to the tool's input, validate the returned sequence against context.translationTable, then return the validated DNA string.

Validation

SEAL validates every optimizer result before returning it. The checks:

  • Output is normalized to uppercase DNA, with U rewritten to T.
  • Output length must match the input length.
  • Bases before the active reading frame and any trailing partial codon must be preserved.
  • The translated protein must match the input under the active NCBI translation table.

If a result fails any check, optimization raises an error naming the optimizer rather than returning an altered protein. This applies to built-in and custom optimizers alike.
