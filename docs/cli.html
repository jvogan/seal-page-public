CLI reference

This guide covers source and direct-edition tools. These tools are not bundled with the first Store release. Compare editions.

The Rust seal CLI runs sequence analysis and selected workspace commands. The source checkout also provides a TypeScript CLI with additional block commands.

Sequence commands generally accept a sequence via a positional argument (a raw string, a file path, or a library name) or stdin. Most commands support --json for machine-readable output and work well in pipelines.

Running the CLI

The desktop installer does not install the CLI. Examples beginning with seal use the Rust binary. Commands beginning with npm --silent run dev:cli -- use the TypeScript implementation.

Install the Rust CLI

Use a SEAL source checkout and a stable Rust toolchain. On macOS, install Xcode Command Line Tools for the native compiler. From the checkout root, build and install the binary:

cargo install --path rust/crates/seal-cli --locked
export PATH="${CARGO_HOME:-$HOME/.cargo}/bin:$PATH"
seal --help
seal analyze ATGAAAGAATTCTAA

cargo install places the binary in Cargo's bin directory. The PATH setting applies to this shell; add it to your shell configuration to use seal in later sessions.

To build a binary in the checkout instead of installing it, use:

cargo build --manifest-path rust/Cargo.toml -p seal-cli --release --locked
./rust/target/release/seal --help

The path shown is Cargo's default output location. If you set CARGO_TARGET_DIR, use that directory instead. The Rust CLI builds independently of the desktop app and Node.js dependencies.

Run the TypeScript CLI

From your source checkout, select the Node.js version in .nvmrc, then install the locked dependencies:

npm ci
npm --silent run dev:cli -- --help
npm --silent run dev:cli -- analyze ATGAAAGAATTCTAA

The TypeScript CLI runs through the checkout's Node.js runtime and native SQLite dependency. It does not require the Rust seal binary. Use the repository's setup instructions if native dependencies need compilation.

Use npm --silent when capturing output or using a pipeline so npm's script banner stays out of the result. For a machine-readable response, also select the command's --json option.

blocks add, blocks translate, and blocks link-parts are available through the TypeScript CLI. Both implementations can use the desktop workspace when you set the active database path.

Differences between the Rust and TypeScript CLIs

A few flags are specific to one CLI:

  • TypeScript fetch uses --database and --json. The --format genbank option is Rust-only.
  • TypeScript import supports --conversation-id, --dry-run, and --json. Recursive import, repair mode, and structured workspace-export filters are Rust-only.

Database path resolution

The shared-database commands (blocks, checkpoints, conversations, export, features, import, projects) read and write a shared SQLite database. The database path is resolved in this order:

  1. SEAL_DB_PATH environment variable, as an absolute path.
  2. A repo-local .seal/seal.db inside the nearest parent directory that contains package.json or .git.
  3. The platform app-data directory, such as ~/Library/Application Support/io.github.jvogan.seal/seal.db on macOS.

To work with the desktop workspace, open SEAL and copy the active database path from Agent Setup. Set that path before running a workspace command:

export SEAL_DB_PATH="/absolute/path/to/active/seal.db"

Replace the placeholder with the path supplied by SEAL. File names, block IDs, Entry IDs, and checkpoint IDs in the examples also need to match your workspace.

When SEAL_DB_PATH is unset, the TypeScript CLI writes the repo-local .seal/seal.db and prints a stderr notice. Set it to a scratch file to isolate agent or test work from your live workspace.

Analysis and sequence commands

These commands are stateless. They read a sequence, compute a result, and print it. They do not touch the shared database. Pass a raw sequence or supported sequence file to the TypeScript blocks add command to save a result. For reports containing labels or tables, use JSON output and extract the sequence first.

align

Align 2 to 10 sequences as a compact multiple sequence alignment.

seal align <seq1> <seq2> [...seqN] [--format clustal|fasta] [--json]

The Rust binary renders a progressive alignment as CLUSTAL or FASTA. The TypeScript CLI adds an --engine selector (seal-progressive, muscle, or clustal-omega). The external engines run their real binary, resolved on PATH. A missing, invalid, or wrong-version binary returns an error and a nonzero exit rather than substituting the built-in aligner, so a result labelled MUSCLE was produced by MUSCLE.

FlagDefaultDescription
--format <fmt>clustalOutput format: clustal or fasta.
--jsonfalseEmit structured JSON output.
 
seal align ATGCGT ATGCAT
seal align seq1.fa seq2.fa seq3.fa --format fasta

codons

Codon usage analysis: count each codon and compute per-amino-acid frequencies. Always reads frame 0 from the start of the sequence. Output is grouped by amino acid, most-used codons first per AA, with stop codons reported last.

seal codons [<input>] [--file <path>] [--format table|json|tsv]
FlagDefaultDescription
<input>stdinInline DNA/RNA sequence or file path.
--file <path>noneFile path (overrides the positional argument).
--format <fmt>tableOutput format: table, json, or tsv.

Output formats:

  • table: human-readable, grouped by amino acid with a #-bar showing relative frequency.
  • json: structured JSON with totalCodons and a codons array. Each entry has codon, aminoAcid, count, and fraction.
  • tsv: tab-separated with columns codon, amino_acid, count, fraction, including a header row.
seal codons ATGAAATAG
echo ATGAAATAG | seal codons
seal codons ATGAAATAG --format json

digest

Simulate a restriction enzyme digest and return the resulting fragment sequences. Supports both linear and circular topology. Use --preview for a dry-run that shows cut positions and fragment sizes without emitting full sequences, which is useful for planning a digest before committing to it.

seal digest [<input>] --enzymes <list> [--topology linear|circular]
                [--preview] [--json]
FlagDefaultDescription
<input>stdinSequence text or file path.
--enzymes <list>requiredComma-delimited enzyme names (required).
--topology linear|circularlinearSequence topology.
--previewfalseShow cut positions and fragment sizes only (dry-run).
--jsonfalseEmit structured JSON output.

When --preview is set, the command prints the enzyme name and cut position for each recognition site found, plus the resulting fragment size list in base pairs. No fragment sequences are emitted. Combine with --json to get a DigestPreviewOutput object with cuts, fragmentSizes, and fragmentCount fields.

seal digest ATGAAAGAATTCGGATCC --enzymes EcoRI
seal digest myseq.fa --enzymes EcoRI,BamHI
seal digest ATGAAAGAATTCGGATCC --enzymes EcoRI --topology circular
seal digest ATGAAAGAATTCGGATCC --enzymes EcoRI,BamHI --preview --json

fetch

Fetch a sequence record from NCBI E-Utilities by accession number. Queries NCBI's nuccore (nucleotide) or protein database via the efetch API. Output defaults to GenBank flat-file text.

seal fetch <accession> [--db nuccore|protein] [--format genbank|fasta|json]
FlagDefaultDescription
<accession>requiredGenBank/RefSeq accession (required).
--db nuccore|proteinnuccoreNCBI database to query. Auto-detected for proteins.
--format genbank|fasta|jsongenbankOutput format.

Output formats:

  • genbank (default): full GenBank flat-file text as returned by NCBI.
  • fasta: FASTA text as returned by NCBI.
  • json: parsed JSON object with fields accession, name, definition, organism, length, sequence, and db.

When --db is left at the default (nuccore), the accession prefix is inspected. Accessions starting with NP_, XP_, YP_, WP_, or AP_ are silently upgraded to the protein database. NCBI may return HTTP 429 (rate limit, wait and retry), HTTP 400/404 or an empty body (accession not found), or a 200 with an error message body for an unknown accession, which is detected and reported as a clear error.

seal fetch NM_000518
seal fetch NM_000518 --format json
seal fetch NP_001234 --db protein

gibson

Simulate Gibson Assembly of two or more overlapping fragments.

seal gibson <frag1> <frag2> [<fragN>...] [--min-overlap <n>] [--max-overlap <n>] [--circular] [--validate] [--json]
FlagDefaultDescription
--min-overlap <n>15Minimum homology-arm overlap in bp. An overlap shorter than this fails.
--max-overlap <n>100Maximum overlap length to search.
--circularfalseCircular assembly. The last fragment must also overlap the first (closing seam).
--validatefalseValidate overlaps only; do not assemble.
--save <name>noneSave the assembled sequence to the local library.
--jsonfalseEmit structured JSON output.

The product length is sum(fragment lengths) - sum(overlap lengths); each overlap appears exactly once. With --circular the closing overlap (last to first) is required, and a missing one is a hard error, not a silently-linear product.

seal gibson insert.fa vector.fa --min-overlap 25
seal gibson part1.fa part2.fa part3.fa --circular --json
seal gibson a.fa b.fa --validate --min-overlap 30

exportPrint an entry as --format fasta|genbank|markdown (default fasta).

sites

Find restriction enzyme recognition sites in a DNA sequence. Scans the built-in default enzyme panel unless --enzymes restricts the set. Use --unique to keep only enzymes that cut exactly once (useful for directional cloning). Use --non-cutter to invert the output and list enzymes that have no recognition site in the sequence.

seal sites [<input>] [--enzymes <list>] [--unique] [--non-cutter] [--json]
FlagDefaultDescription
<input>stdinSequence text or file path.
--enzymes <list>default panelComma-delimited enzyme names to check.
--uniquefalseOnly report enzymes that cut exactly once.
--non-cutterfalseList enzymes with no recognition site (inverted output).
--jsonfalseEmit structured JSON output.

When --non-cutter is set, the command prints the names of enzymes from the selected panel that have no recognition site in the sequence, rather than the list of cut positions. Combine with --enzymes to check whether a specific set of enzymes can be used to linearize a construct without cutting it unexpectedly. With --json the output is a NonCutterOutput object with enzymes (string array) and count fields.

Curated presets and --list-presets are available through the TypeScript CLI.

seal sites ATGAAAGAATTCGGATCC --enzymes EcoRI,BamHI
npm --silent run dev:cli -- sites myseq.gb --preset golden-gate-type-iis --non-cutter
npm --silent run dev:cli -- sites myseq.gb --preset common-mcs --unique --json

blocks add

Materialize any sequence, a translation, a digest fragment, a PCR amplicon, or an assembled construct, as a workspace block. This is the bridge from the stateless analysis commands (which only print) into the workspace: pipe their output here. extract-selection only slices a substring of an existing block; add accepts a free-form sequence and can set an arbitrary --type and --parent.

FlagDefaultDescription
[seq]stdinSequence (bare string), a --file-style path, or piped via stdin.
--name <n>input name / blockName for the new block.
--conversation-id <id>CLI scratchTarget conversation (id or title). Ignored when --parent is set.
--parent <name|id>none (top-level)Parent block. Makes the new block a nested child (inherits the parent's conversation).
--type <t>auto-detectdna, rna, or protein. Override the detector (for example, force protein).
--topology <t>linearlinear or circular.
--overhang5 / --overhang3 <seq>noneSticky-end overhangs (for example, from a digest --json fragment).
--overhang5-type / --overhang3-type <kind>noneOverhang kind (5prime, 3prime, or blunt).

checkpoints

Save, restore, list, and diff block checkpoints in the shared database. The registered delete subcommand remains for script compatibility but fails closed until recoverable checkpoint trash exists.

seal checkpoints <subcommand> [args]
SubcommandDescription
saveSave a snapshot of a block as a new checkpoint.
restoreTransactionally restore a block from a checkpoint.
deleteCompatibility-only command that rejects without changing data.
listList all checkpoints for a block, newest-first.
diffDiff two checkpoints on the same block.

save takes --block <name|id> (required) and an optional --label <label> (auto-generated by default). restore takes --block <name|id> and --checkpoint-id <id> (both required). list takes --block <name|id> (required). diff takes --checkpoint-a <id> (the "before") and --checkpoint-b <id> (the "after"), both required. Calling delete returns a stable disabled-operation error before target lookup or mutation.

seal checkpoints save --block seal-synthetic-backbone --label "before BamHI digest"
seal checkpoints list --block seal-synthetic-backbone
seal checkpoints diff --checkpoint-a cp-abc --checkpoint-b cp-xyz
seal checkpoints restore --block seal-synthetic-backbone --checkpoint-id cp-abc

conversations

Manage conversations in the shared database: create, rename, list, get, and move conversations between projects. The registered delete subcommand fails closed because permanent conversation deletion is not recoverable.

seal conversations <subcommand> [args]
SubcommandDescription
createCreate a new conversation.
renameRename an existing conversation (fuzzy title resolution).
deleteCompatibility-only command that rejects and directs the user to Archive and Restore in the app.
listList all conversations.
getGet a single conversation by title or id.
moveMove a conversation to a different project (or unassign it).

create <title> (title required) takes an optional --project-id <id>. rename <name> <new-title> takes the current title or id then the new title. get <name> takes a single name-or-id positional argument. move <name> (name required) takes either --project-id <id> or --unassign (mutually exclusive), the latter removing the project assignment. Calling delete changes no data; archive the Entry in SEAL and restore it from Archived when needed.

Fuzzy name resolution runs in three steps: exact id, case-insensitive exact title, then case-insensitive partial match (unique matches resolve, multiple matches return suggestions).

seal conversations create "CRISPR experiment 1"
seal conversations create "Cloning workflow" --project-id proj-abc
seal conversations rename "CRISPR experiment 1" "CRISPR round 2"
seal conversations move "CRISPR round 2" --project-id proj-xyz
seal conversations move "CRISPR round 2" --unassign

export

Export blocks from the shared workspace in various formats: CSV, Markdown, slide-friendly Markdown summary, GenBank, or a full JSON dump.

seal export <subcommand> [--output <path>]
SubcommandDescription
csvCSV summary table (one row per block).
markdownMarkdown document (one section per block).
slide-summaryCompact slide-friendly Markdown (one bullet per block).
genbankGenBank export for one block, all blocks, or one file per block.
workspace-jsonFull JSON dump of every block in the scratch workspace.

All subcommands accept --output <path> to write to a file instead of stdout. Per-subcommand flags:

SubcommandFlagDefaultDescription
csv--include-featuresfalseAdd a features section below the table.
markdown--include-analysisfalseInclude GC% and length analysis rows for each block.
slide-summary--title <t>"Sequence Summary"Optional title for the document.
genbank--block <id>noneExport only one block; omit to export all blocks.
genbank--output <path>noneWrite a single GenBank file, possibly multi-record.
genbank--output-dir <dir>noneWrite one .gb file per exported block.
 
seal export csv --include-features --output report.csv
seal export markdown --include-analysis
seal export slide-summary --title "PCR results"
seal export workspace-json --output workspace.json
seal export genbank --block block-abc --output plasmid.gb
seal export genbank --output-dir genbank-export

features

Manage feature annotations on workspace sequence blocks: add, update, delete, and list features on any block in the CLI scratch workspace.

seal features <subcommand> [args]
SubcommandDescription
addAdd a feature to a block.
updateUpdate a feature on a block by feature id.
deleteDelete a feature from a block by feature id.
listList all features on a block.
SubcommandFlagDefaultDescription
add--block <id>requiredBlock id in the CLI scratch workspace (required).
add--feature-json <j>requiredFeature JSON with required fields type, name, start, end; id is auto-generated if absent (required).
update--block <id>requiredBlock id in the CLI scratch workspace (required).
update--feature-id <id>requiredId of the feature to update (required).
update--patch-json <j>requiredPartial feature JSON; only supplied fields are merged (required).
delete--block <id>requiredBlock id in the CLI scratch workspace (required).
delete--feature-id <id>requiredId of the feature to delete (required).
list--block <id>requiredBlock id in the CLI scratch workspace (required).

Position rules: linear blocks require start <= end, both in [0, block_length]. Circular blocks allow wrap-around (start > end), each value in [0, block_length].

# Add a gene feature
seal features add --block block-id-abc \
  --feature-json '{"id":"feat-reporter","type":"gene","name":"Synthetic Reporter DNA","start":0,"end":720}'

# Update only the color field
seal features update --block block-id-abc --feature-id feat-reporter \
  --patch-json '{"color":"#0000ff"}'

# List all features on a block
seal features list --block block-id-abc

import

Import one or more FASTA or GenBank files, supported sequence directories, or recognized structured workspace exports into the shared workspace. Multi-record files (multiple > headers or multiple LOCUS blocks) are split automatically into separate blocks. Recognized inventory database layouts are detected automatically.

seal import <path> [<path>...] [--recursive] [--conversation-id <id>] [--format json|text]
FlagDefaultDescription
<paths>requiredOne or more file or directory paths to import.
--recursivefalseRecursively import supported files from ordinary directories.
--conversation-id <id>CLI scratchTarget conversation id.
--dry-runfalseParse and report records without writing blocks.
--repair-existingfalseUpdate matching existing blocks instead of creating duplicates.
--import-missingfalseWith --repair-existing, create records that do not match.
--overwrite-featuresfalseWith --repair-existing, replace non-empty feature arrays.
--format json|textjsonOutput format.
 
seal import plasmid.gb
seal import primers.fa vector.gb insert.fa
seal import seqs.fa --conversation-id conv-abc123
seal import /path/to/workspace-export --recursive --dry-run --format text
seal import annotated.gb --repair-existing --import-missing --format text

projects

Manage projects in the shared database: create, rename, delete, list, get, and update project color.

seal projects <subcommand> [args]
SubcommandDescription
createCreate a new project.
renameRename an existing project (fuzzy name resolution).
deleteDelete a project (child conversations have projectId set to null).
listList all projects.
getGet a single project by name or id.
set-colorUpdate the color of a project.

create <name> (name required) takes an optional --color <hex> (default "#6b7280"). rename <name> <new-name> and get <name> take name-or-id positional arguments. set-color <name> <color> takes a name-or-id then a hex color. Before delete <name>, run projects get and supply --confirm, --expected-updated-at <ms>, --expected-conversation-count <n>, one --expected-conversation-id <id> per assigned Entry, and --project-id <id> when the positional name is not already the exact project ID. The guarded child unassignment, conditional delete, and durable audit tombstone commit atomically. Fuzzy name resolution runs the same three steps as conversations: exact id, case-insensitive exact name, then case-insensitive partial match.

seal projects create "CRISPR campaign"
seal projects create "Library screen" --color "#ef4444"
seal projects rename "CRISPR campaign" "CRISPR campaign v2"
seal projects set-color "Library screen" "#22c55e"
seal projects delete "CRISPR campaign v2" \
  --confirm \
  --project-id proj-id-abc \
  --expected-updated-at 1712345678000 \
  --expected-conversation-count 2 \
  --expected-conversation-id conv-a \
  --expected-conversation-id conv-b

Color systems reference

SEAL uses several independent color systems. Not all of them respond to the same UI toggles. This section documents which systems are affected by each appearance setting.

Amino-acid classification colors

The amino-acid classification tokens (--aa-class-*) are controlled by the Vivid · Wong AA-color palette toggle in Settings → Appearance → Accessibility. When on, it overrides five chemistry-class hues with the Wong (2011) colorblind-safe palette:

TokenDefaultWong (toggle on)
--aa-class-hydrophobic#f59e0b#E69F00
--aa-class-polar#22c55e#009E73
--aa-class-positive#60a5fa#0072B2
--aa-class-negative#fb7185#D55E00
--aa-class-special#a78bfa#CC79A7

The toggle also overrides --amber and --green (used by the Chou-Fasman secondary-structure bars) and --coil-color to matching Wong hues, so protein-track secondary-structure bars remain distinguishable under all three common CVD types (deuteranopia, protanopia, tritanopia). Scope: amino-acid tracks, protein inspector, Chou-Fasman bars, and AA-class feature pills. It does not affect DNA base colors.

DNA base colors

The DNA base tokens (--base-a, --base-t, --base-g, --base-c) are controlled by the light/dark theme only. These tokens are defined per theme and are not gated by the Wong AA-color palette toggle.

BaseLight themeDark theme
A#198841#4ade80
T#ed0c0c#f87171
G#8f7303#facc15
C#0870f2#60a5fa

Users who need colorblind-safe DNA base colors should use the High contrast toggle (Settings → Appearance → Accessibility), which boosts all foreground and background contrast, or apply a system-level color filter via OS accessibility settings.
