CRISPR guide design

This guide includes source and direct-edition features. Check the edition comparison for the first Store release. Screenshots and recordings show the direct edition. Compare editions.

Design CRISPR Guides scans a sequence, or a region you select inside it, for SpCas9 sites with an NGG PAM. It returns a ranked list of 20 nt protospacers with position, cut site, GC content, and composition flags, and it can scan a reference you choose for other sites the same spacer could bind.

Design guides for a region

Open a DNA or RNA block, select the region you want to target, then choose Actions, Transform, Design CRISPR Guides. The dialog scans the block and lists candidates straight away.

With no selection the scan covers the whole sequence, and the callout at the top of the dialog says so. With a selection the callout reports the scoped range and its length in bases, and the region rule decides which guides qualify.

The nuclease parameters are fixed, and the dialog states them along with what the quality value is: SpCas9 · PAM NGG · 20 nt guide · Quality is a sequence-only heuristic. An RNA block is read as DNA for the scan, with U treated as T.

Guide anatomy

The scan matches a PAM first, then takes the 20 bases immediately 5' of it as the protospacer. SpCas9 makes a blunt double-strand break 3 bp from the PAM, and the same geometry applies on both strands.

Region rules and strand

Two controls sit above the results. PAM strand chooses which strands to scan: Both (the default), Forward, or Reverse. Region rule decides which guides a selection keeps.

Region ruleKeeps a guide when
Cut site in regionThe cut site falls inside the selection. This is the default, and it is the rule to use for a knockout at a chosen position.
Protospacer insideThe whole 20 nt protospacer lies inside the selection.
Overlaps regionThe protospacer overlaps the selection at all.

A collapsed or inverted selection is treated as no selection, so the scan falls back to the whole sequence and every guide qualifies.

Rows sort by quality, highest first, then by position. Click a row to select it.

The list returns up to 200 ranked guides. The footer reports three separate numbers: how many guides the list holds, how many PAM sites the scan matched on the strands you selected before the region rule and the sequence-end check removed candidates, and the length of the block in bases.

The quality heuristic

Quality starts at 100 and subtracts a penalty for each composition problem in the spacer. Every penalty maps to a flag on the row, so any value can be explained by reading its flags. The result is clamped to the range 0 to 100.

CheckFlagPenalty
GC outside 40 to 65 percent, and within 30 to 70low_gc or high_gc10
GC outside 30 to 70 percent, and within 20 to 80low_gc or high_gc25
GC below 20 or above 80 percentlow_gc or high_gc40
A run of exactly four T basespoly_t30
A run of five or more T basespoly_t50
A run of five or more A, G, or C baseshomopolymer15
A base outside A, C, G, Tambiguous_base15
Spacer equal to its own reverse complementself_complementary20
Cut site away from the center of a selected regionnoneup to 10

Poly-T carries the largest penalty because a run of four or more T bases can terminate Pol III transcription from a U6 or H1 promoter. GC content is measured over ACGT bases only, so an ambiguous base is excluded from the denominator and flagged separately. The centrality term applies only when you scope the scan to a region.

Quality is a sequence-composition heuristic and nothing more. It reads the bases of the spacer, plus how central the cut site is in a region you selected. It is not a measure of editing efficiency, and it is not evidence about where else a spacer could bind. Two guides with the same quality value can behave very differently in an experiment. The dialog says as much on the parameter line above the list, and the value is stored on an annotation under a named model, seal-sequence-heuristic-v1, so it stays attributable.

What the guide scan covers

The guide scan covers the sequence in the block you opened it on, and the region you select inside that block. It enumerates candidate sites there and scores their composition. To look for other places a spacer could bind, run the off-target analysis below.

The scan reads the sequence from the first base to the last. On a circular block that covers the sequence as stored, so a site spanning the join between the last base and the first is outside the scan.

A PAM is called only on confirmed A, C, G, or T bases. An ambiguous base anywhere in the PAM window, including the N position of NGG, leaves that site uncounted rather than guessed.

When nothing matches, the dialog reports that no NGG PAM sites were found in the selected region, and suggests widening the selection or switching strands. If the selection is shorter than 20 nt it says so too. Read an empty list the way you would read any scan result: no sites found under these parameters and reference scope.

Off-target analysis

Selecting a guide opens an Off-target analysis panel below the list. It searches a reference sequence you choose for other sites the same spacer could bind. The panel header names the engine and its scope: SEAL local sequence scan, current sequence only, runs on this device.

ControlWhat it sets
Reference scopeThe sequence to search. It defaults to the block you opened the dialog on. Any other DNA block in the workspace, up to 5,000,000 bases, can be chosen instead, and each option is listed with its length.
Maximum mismatchesThe inclusive mismatch ceiling, from 0 to 6. The panel opens at 3.

Choose Analyze selected guide to run. The scan runs in a worker, so the dialog stays usable while it works, and the button becomes Cancel for the duration. A spacer containing an ambiguous base cannot be analyzed, and the panel asks for an A/C/G/T-only guide instead.

Result states

The chip in the panel header always reports one of six states.

StateMeaning
Not runNo analysis has run for this guide, reference, and mismatch ceiling.
RunningA scan is in progress and can be canceled.
CompleteThe scan finished and every site it found is in the result.
IncompleteThe scan finished, and the retained hit list reached its 100-site cap. The counts still cover every site found.
StaleThe mismatch ceiling changed, or a run was canceled, after a result already existed. Run again before storing the evidence with a guide.
FailedThe run returned an error, which the panel shows in full.

Reading a result

A finished run reports the total number of sequence-local sites, a breakdown by mismatch count, and how many intended targets it excluded. When the reference is the block the guide came from, the guide's own site is validated against the reference and excluded from the count, so the total covers other sites only. Choosing a different reference means the source coordinates no longer apply, and nothing is excluded.

Sites are listed by position, strand, mismatch count, and PAM, sorted by mismatch count and then position, with the first eight shown and a line reporting how many of the total are on screen. Where the reference has unknown or degenerate bases inside a site, the panel says so, and the mismatch count for that site is the minimum number of known mismatches.

When a run finds nothing, the panel reports no sequence-local sites under these parameters. Read that as: no sites found under these parameters and reference scope. It is a statement about the reference you chose and the ceiling you set, and it holds for those.

What the analysis covers

The scan is mismatch-only, it reads both strands, and it runs as a linear scan. DNA and RNA bulges, variants, circular-junction sites, and the rest of a genome are not included. To search another locus or construct, import it as a DNA block and choose it under Reference scope. Whole-genome references need a genome-grade adapter.

The analysis reads a reference of up to 5,000,000 bases, which covers constructs and locus-sized blocks. Longer blocks are left out of the Reference scope list. The block you opened the dialog on is always listed, so if that block is itself over the limit, the run reports that analysis is limited to 5,000,000 bases and the chip goes to Failed.

Like the guide scan, the analysis reads the reference from its first base to its last, so a site spanning the join of a circular sequence sits outside it.

A result describes the reference you chose, at the mismatch ceiling you set, at the moment it ran. Rerun it whenever the guide, the reference, or the ceiling changes.

SEAL is research software. A guide list and a scan result are starting points for design work and for your own validation, and they are not clinical guidance.

Annotate a guide

Select a row and choose Add Guide as Feature. SEAL adds a misc_feature spanning the protospacer, on the strand the guide reads, named for the strand and the 1-based start position. The spacer, the PAM, the PAM span, the cut site, the GC content, the quality value and its model name, and the flags are stored on the feature, so the numbers travel with the annotation.

If the selected guide has a finished off-target run against the current reference, a compact summary goes on the feature too: the engine and its version, the nuclease profile, the reference identity, length, and fingerprint, the mismatch ceiling, the total sites and their breakdown by mismatch count, and when the run completed. The full hit list stays with the run rather than the annotation, so sequence documents stay small.

The dialog stays open after an add, so you can annotate several guides from one scan. A guide already annotated at the same position with the same spacer is skipped rather than duplicated, and its row shows an Added chip.

Each add writes a Guide Design event to the Activity trail, titled for the block and carrying a count of the annotations added. See Editing and annotation for how features behave once they are on a block.

Copy guides out

Copy all as FASTA copies every guide in the list, in list order. Each header carries the block name, the rank, the strand, and the 1-based protospacer start.

The copy button on a row copies that spacer on its own, with no PAM and no header, ready to paste into an order form.

Guide design and off-target analysis run in the desktop app. There is no seal command and no MCP tool that runs either scan, so an agent reads guides through the annotations you keep, with feature_list. See the MCP tool reference.
