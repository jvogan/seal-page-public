IO contract

This guide covers source and direct-edition tools. These tools are not bundled with the first Store release. Compare editions.

The documented JSON shapes used by SEAL's CLI and MCP surfaces. Some overlapping commands intentionally align; the Rust CLI, TypeScript CLI, MCP server, and desktop app are not one universal runtime and have explicit capability boundaries.

The MCP envelope is the source of truth for MCP tools. Where a Rust or TypeScript CLI command advertises parity, its --json or --format json payload aligns with the corresponding MCP data payload. Do not assume an undocumented command, flag, algorithm, or field is interchangeable across surfaces; see the CLI differences and each command section.

The MCP envelope

Every MCP tool response uses one envelope. On success, the result lives in data and a workspaceSummary reports the current workspace:

{ "ok": true, "data": <payload>, "workspaceSummary": { "count": 0, "names": [] } }

On failure, the envelope carries an error message and suggestions instead:

{ "ok": false, "error": "human-readable message", "suggestions": ["..."] }

The CLI emits the <payload> directly, with no envelope, because the CLI tools are shell tools rather than RPC endpoints. To compare shapes, compare the data field of an MCP response against the raw CLI JSON.

Shared-database commands (projects, conversations, blocks, features, checkpoints, export, import) write to the same SQLite workspace the app uses. The CLI subcommands stamp write_source: "cli" on every write, and the matching MCP tools stamp write_source: "mcp", so the app file watcher can attribute the change. Each scope except bulk import has an MCP tool equivalent that returns the same shapes as the CLI subcommand. See the architecture overview.

Conventions

  • camelCase fields. Every JSON field name is camelCase, in both CLI and MCP output.
  • Percentages are strings. gcContent and atContent are formatted to two decimal places with a % suffix, for example "33.33%".
  • RNA is normalized. RNA input (U bases) is converted to DNA (U to T) before analysis. The composition field counts T, never U.
  • Arrays may truncate in MCP. The MCP server may cap large arrays (ORFs over 20, restriction sites over 50) and add a warnings field. The CLI does not truncate.
  • CLI exit codes. Exit 0 on success, 1 on error. The JSON payload goes to stdout; errors go to stderr.

analyze

Full sequence analysis: GC and AT content, molecular weight, melting temperature, nucleotide composition, an ORF summary, and restriction sites. Run it from the CLI or call the analyze MCP tool.

seal analyze --json ATGAAATAAGAATTC

The payload:

FieldTypeDescription
lengthnumberSequence length in base pairs.
gcContentstringGC fraction as a percentage string, for example "33.33%".
atContentstringAT fraction as a percentage string.
molecularWeightnumberEstimated molecular weight in Daltons (single-stranded DNA).
meltingTempnumber | nullWallace-rule melting temperature in °C; null for an empty sequence.
compositionobjectBase counts: A, T, G, C, and N for non-canonical or ambiguous bases.
orfsobjectORF summary: count, longest (an OrfRecord or null), and all (an OrfRecord array, capped at 20 in MCP).
restrictionSitesSiteRecord[]Restriction enzyme cut sites found in the sequence.

An OrfRecord describes one open reading frame:

FieldTypeDescription
startnumber0-based start position.
endnumber0-based end position (exclusive).
framenumberReading frame: 0, 1, or 2.
strandnumber1 for forward (+), -1 for reverse (-).
lengthnumberNucleotide length of the ORF.
aminoAcidsnumberAmino acid count (length / 3, excluding the stop).
startCodonstringStart codon, for example "ATG".
stopCodonstringStop codon, for example "TAA"; an empty string for a run-off ORF.

A SiteRecord describes one restriction cut site:

FieldTypeDescription
enzymestringEnzyme name, for example "EcoRI".
positionnumber0-based position of the recognition sequence.
cutPositionnumber0-based absolute position of the cut in the original sequence.
recognitionSequencestringRecognition sequence, for example "GAATTC".
overhangstringOverhang type: "5prime", "3prime", or "blunt".

The full payload for ATGAAATAAGAATTC:

{
  "length": 15,
  "gcContent": "13.33%",
  "atContent": "86.67%",
  "molecularWeight": 4484.895,
  "meltingTemp": 26.0,
  "composition": { "A": 7, "T": 6, "G": 1, "C": 1, "N": 0 },
  "orfs": {
    "count": 1,
    "longest": {
      "start": 0, "end": 9, "frame": 0, "strand": 1,
      "length": 9, "aminoAcids": 2, "startCodon": "ATG", "stopCodon": "TAA"
    },
    "all": [
      {
        "start": 0, "end": 9, "frame": 0, "strand": 1,
        "length": 9, "aminoAcids": 2, "startCodon": "ATG", "stopCodon": "TAA"
      }
    ]
  },
  "restrictionSites": [
    {
      "enzyme": "EcoRI",
      "position": 9,
      "cutPosition": 10,
      "recognitionSequence": "GAATTC",
      "overhang": "5prime"
    }
  ]
}

The same call as an MCP tool wraps that payload in the envelope:

{
  "ok": true,
  "data": { "length": 15, "gcContent": "13.33%", "atContent": "86.67%", "...": "..." },
  "workspaceSummary": { "count": 0, "names": [] }
}

codons

Codon usage analysis: a count of each codon and a per-amino-acid frequency. It reads frame 0 from the start of the sequence and reports stop codons last. There is no dedicated codons MCP tool; use transform with calculate_cai or codon_optimize for related operations.

seal codons ATGAAATAG --format json

The payload is totalCodons (the count of complete triplets) and a codons array. Each entry:

FieldTypeDescription
codonstringThree-letter uppercase DNA codon, for example "ATG".
aminoAcidstringSingle-letter amino acid code; "*" for a stop codon.
countnumberRaw count of this codon.
fractionnumberUsage fraction within this amino acid (0.0 to 1.0).

Entries sort alphabetically by amino acid (stops last), then by descending count, with codon-string ties broken alphabetically. The tsv format emits a header row followed by codon, amino_acid, count, and fraction columns, with fraction to four decimal places.

{
  "totalCodons": 3,
  "codons": [
    { "codon": "AAA", "aminoAcid": "K", "count": 1, "fraction": 1.0 },
    { "codon": "ATG", "aminoAcid": "M", "count": 1, "fraction": 1.0 },
    { "codon": "TAG", "aminoAcid": "*", "count": 1, "fraction": 1.0 }
  ]
}

fetch

Fetch a record from NCBI E-Utilities by accession. The query hits the nuccore (nucleotide) or protein database. Protein accession prefixes (NP_, XP_, YP_, WP_, AP_) route to the protein database even without --db. With --format genbank (the default) or --format fasta, the output is the raw text NCBI returns. With --format json, the payload is:

FieldTypeDescription
accessionstringAccession from the ACCESSION line, or the query value.
namestringLocus name from the LOCUS line.
definitionstringThe DEFINITION field, joined to one line with spaces.
organismstringOrganism name from the ORGANISM line.
lengthnumberLength in base pairs or amino acids, computed from the ORIGIN section.
sequencestringUppercase sequence letters from the ORIGIN section.
dbstringDatabase queried: "nuccore" or "protein".
 
{
  "accession": "U49845",
  "name": "SCU49845",
  "definition": "Saccharomyces cerevisiae TCP1-beta gene, partial cds.",
  "organism": "Saccharomyces cerevisiae",
  "length": 5028,
  "sequence": "GATCCTCCATATACAACGG...",
  "db": "nuccore"
}

info

Quick sequence type detection and basic stats. There is no info MCP tool; use analyze for full analysis or parse_sequence to detect an input format.

FieldTypeDescription
namestringSequence name, from a FASTA header or the file stem.
sequenceTypestring"dna", "rna", or "protein".
lengthnumberLength in bases or amino acids.
gcContentnumber | nullRaw GC fraction (0 to 1); null for protein.
formatstringInput format: "fasta", "genbank", "raw", or "library".
validbooleanTrue if no characters outside the alphabet were found.
invalidCharsstring[]Invalid characters found; empty when valid is true.

The Rust CLI emits sequenceType; the TypeScript CLI emits the shorter key type. Handle either when reading info output.

{
  "name": "ATGCATGC",
  "sequenceType": "dna",
  "length": 8,
  "gcContent": 0.5,
  "format": "raw",
  "valid": true,
  "invalidChars": []
}

orfs

Find every open reading frame in a DNA sequence. The scan covers all six reading frames (three forward, three reverse) for ATG-to-stop stretches that meet a minimum amino-acid length (--min-aa, default 30). ORFs also appear inside the analyze result.

seal orfs ATGAAATAA --min-aa 2 --json

With --json the command emits a flat array of ORF objects, each with the same fields as an OrfRecord: start, end, frame, strand, length, aminoAcids, startCodon, and stopCodon.

[
  {
    "start": 0, "end": 9, "frame": 0, "strand": 1,
    "length": 9, "aminoAcids": 2, "startCodon": "ATG", "stopCodon": "TAA"
  }
]

The standalone orfs command returns a flat array. The analyze command wraps the same records in { count, longest, all } and may cap all at 20 entries in MCP responses.

rc

Compute the reverse complement of a DNA or RNA sequence. Pass --rna to complement with U in the output. There is no rc MCP tool.

FieldTypeDescription
inputstringOriginal input sequence, as read.
outputstringReverse complement.
lengthnumberLength of the output in bases.
 
{ "input": "ATGCGT", "output": "ACGCAT", "length": 6 }

sites

Find restriction enzyme cut sites in a DNA sequence. The scan covers the default panel unless --enzymes restricts the set or --preset selects a curated panel. See restriction digest for the workflow. Restriction sites also appear inside the analyze result.

seal sites ATGAAAGAATTCGGATCC --enzymes EcoRI --json

In normal mode the payload is a SitesOutput object: a sites array plus a count. The sites field names match restrictionSites in the analyze response (enzyme, position, cutPosition, recognitionSequence, overhang).

{
  "sites": [
    {
      "enzyme": "EcoRI",
      "position": 6,
      "cutPosition": 7,
      "recognitionSequence": "GAATTC",
      "overhang": "5prime",
      "strand": 1
    }
  ],
  "count": 1
}

With --non-cutter, the output inverts: a single object listing the enzymes with no recognition site, in the order they were passed to --enzymes.

{ "enzymes": ["EcoRI"], "count": 1 }

digest

Simulate cutting a DNA sequence with the given enzymes and return the resulting fragments. The digest supports linear and circular topology. Use --preview for a dry run that reports cut positions and fragment sizes without emitting full sequences. The digest MCP tool exists, but it returns a restructured payload. Its data object carries enzymes, cutCounts, fragmentCount, and a fragments array whose entries use start and end rather than the CLI's startInOriginal and endInOriginal, so its shape differs from the CLI's flat fragment array.

seal digest ATGAAAGAATTCGGATCC --enzymes EcoRI --json

In normal mode the payload is an array of fragment objects:

FieldTypeDescription
sequencestringFragment sequence (uppercase DNA).
lengthnumberFragment length in bp.
startInOriginalnumber0-based start in the original sequence.
endInOriginalnumber0-based end (exclusive) in the original sequence.
leftEnzymestring | nullEnzyme that cut the left end; null for the leftmost fragment.
rightEnzymestring | nullEnzyme that cut the right end; null for the rightmost fragment.
 
[
  {
    "sequence": "ATGAAAG",
    "length": 7,
    "startInOriginal": 0,
    "endInOriginal": 7,
    "leftEnzyme": null,
    "rightEnzyme": "EcoRI"
  },
  {
    "sequence": "AATTCGGATCC",
    "length": 11,
    "startInOriginal": 7,
    "endInOriginal": 18,
    "leftEnzyme": "EcoRI",
    "rightEnzyme": null
  }
]

With --preview, the output is a single object: the cuts (each with enzyme and cutPosition), the fragmentSizes in order, and a fragmentCount.

{
  "cuts": [{ "enzyme": "EcoRI", "cutPosition": 7 }],
  "fragmentSizes": [7, 11],
  "fragmentCount": 2
}

Shared-database commands

These commands read and write the SQLite workspace. The CLI subcommands and the MCP tools return the same shapes.

projects

CRUD for projects (project_create, project_list, project_get, project_rename, project_set_color, project_delete). A ProjectOutput:

FieldTypeDescription
idstringUUID.
namestringProject name.
colorstringHex color, for example "#6b7280".
conversationIdsstring[]Ids of conversations assigned to this project.
createdAtnumberUnix milliseconds.
updatedAtnumberUnix milliseconds.

projects list returns an array of these. create, get, and set-color return one. rename returns { id, oldName, newName }. Guarded delete returns { deleted, id, unassignedConversationIds }.

conversations

Create, list, get, rename, and project assignment are available through conversation_create, conversation_list, conversation_get, conversation_rename, and conversation_move. The registered conversation_delete compatibility surface always rejects because external permanent deletion lacks a complete crash-safe recovery path. A ConversationOutput:

FieldTypeDescription
idstringUUID.
titlestringConversation title.
projectIdstring | nullAssigned project id, or null.
sequenceBlockIdsstring[]Ordered block ids.
createdAtnumberUnix milliseconds.
updatedAtnumberUnix milliseconds.

list returns an array; create, get, and move return one; rename returns { id, oldTitle, newTitle }.

features

Feature annotation CRUD on a block (feature_add, feature_update, feature_delete, feature_list). A FeatureRecord:

FieldTypeDescription
idstringFeature id, auto-generated if not supplied.
typestringFeature type, for example "gene", "CDS", "misc_feature".
namestringHuman-readable name.
startnumber0-based start position (inclusive).
endnumber0-based end position (exclusive).
strandnumber?1 forward, -1 reverse; omitted if absent.
colorstring?Hex color; omitted if absent.
notesstring?Free-text notes; omitted if absent.
locationsarray?Compound-location sub-parts, each { start, end }; omitted if absent.

feature_add returns { feature, totalFeatures }. feature_update returns { feature }. feature_delete returns { removed }. feature_list returns { features, count }.

checkpoints

Block checkpoint save, restore, diff, list, and delete (checkpoint_save, checkpoint_restore, checkpoint_delete, checkpoint_list, checkpoint_diff). A checkpoint snapshots a block's raw, topology, type, features, and scars; restore runs in a single transaction.

  • save returns { id, label, blockId, timestamp }.
  • list returns { blockId, blockName, count, checkpoints }, where each summary carries id, label, blockId, conversationId, timestamp, and writeSource.
  • diff returns a DiffOutput with rawChanged, rawLengthDelta, topologyChanged, typeChanged, featuresAdded, featuresRemoved, featuresChanged, and scarsDelta.
  • delete returns { deleted }.
  • restore returns the restored block's full record on success, or an error envelope on failure.

blocks

Block manipulation: reorder, extract a sub-sequence, or annotate a selection (block_reorder, block_extract_selection, block_annotate_selection).

  • block_reorder returns { ok, reordered }.
  • block_extract_selection returns { ok, id, name, length, parentId }.
  • block_annotate_selection returns { ok, feature, totalFeatures }.

On failure, all three return { ok: false, error, suggestions }.

export

Export workspace blocks to CSV, Markdown, or JSON (export_csv, export_markdown, export_slide_summary, export_workspace_json, export_package). See reports and packages. When you pass --output <path>, each subcommand returns { ok, format, count, path }. Without --output, content goes to stdout with no envelope.

The export_package MCP payload describes a zip: a filename, mimeType, byteLength, an optional base64Zip, a manifest (with packageVersion, generatedAt, source ids, and a files list carrying path, mimeType, sizeBytes, crc32, lossless, and verifyByReimport), and a validationMarkdown.

import

Import FASTA, GenBank, sequence directories, or recognized structured workspace exports into the workspace. See import and export. The payload:

FieldTypeDescription
okbooleanWhether the import succeeded.
importedImportedEntry[]One entry per imported record.
countnumberNumber of records imported.
dryRunbooleanWhether this was a dry run.
warningsstring[]Any warnings raised during import.

Each ImportedEntry carries id, name, length, format ("fasta" or "genbank"), featureCount, topology, and optional accession and action fields.
