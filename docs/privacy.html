Privacy

SEAL is local-first. Workspace data stays on your device unless you explicitly start a network-backed fetch, prediction, hosted-model request, source-edition Notion diagnostic, or external-agent action. SEAL sends no background telemetry, analytics, or crash reports.

Mac App Store edition

The first Store configuration uses sandbox-managed default storage and user-selected workspace folders. It does not enable terminal launching, external tool runtimes, or hosted-provider credential storage. See the Store privacy summary and Edition differences.

Direct and source editions: local data

The implementation details below describe direct and source builds. Do not use their default filesystem paths as the Store edition's storage locations.

  • SQLite workspace. Entries, sequence blocks, features, annotations, checkpoints, notebooks, Activity, and database-backed settings are stored in seal.db.
  • Local analysis. Restriction maps, ORFs, GC windows, local alignment, gel simulation, cloning plans, translation, and ordinary analysis remain local unless you explicitly export or share them.
  • Imported files. Supported bioinformatics files are read locally and their parsed content is saved to local persistence.
  • Electron userData. Window state, Chromium storage, UI preferences, and secure-keys.json live in a separate local directory.
  • Browser fallback. Browser mode uses its own IndexedDB and localStorage profile, separate from both native directories.

The source MCP server is local stdio and does not make outbound network calls by itself. An external agent connected to it can still transmit context to its own provider. Native processes and the Rust CLI are governed separately from the renderer Content Security Policy.

Provider key storage

The local unsigned package disables in-app provider-key storage because its Chromium keychain mode does not provide secure credential storage. Existing encrypted sidecar data remains untouched. External agents and terminal tools continue to use their own credential stores.

Builds with OS-backed Electron safeStorage can encrypt hosted sequence-model keys through macOS Keychain. Ciphertext is stored in secure-keys.json under the separate Electron userData directory, and plaintext is not returned to the renderer.

No automatic collection

  • No telemetry or usage analytics.
  • No automatic crash-report upload.
  • No background cloud synchronization.
  • No SEAL cloud account or SEAL-hosted workspace service.

Data storage locations

The native app intentionally uses two separate directory trees.

SQLite workspace~/Library/Application Support/io.github.jvogan.seal/seal.dbEntries, sequences, notebooks, checkpoints, Activity, and database settings.
Electron userData~/Library/Application Support/SEAL/secure-keys.json, window state, Chromium localStorage, and browser-profile data.

Windows and Linux use their platform application-data and config directories. Browser fallback data is in the browser profile that opened SEAL.

Clear all local data

The supported path is Settings → Data → Clear all data. Before clearing the active SQLite workspace, the desktop app creates a verified seal.db.pre-restore-*.backup recovery copy beside it and retains up to five. Settings reports the new recovery path. Delete those copies separately if you also need retained recovery data removed.

Manual removal requires closing every app, browser tab, MCP server, and CLI process using the workspace, then deleting all of the following:

  1. The SQLite workspace directory, including adjacent recovery copies.
  2. The separate Electron SEAL userData directory.
  3. Any SEAL IndexedDB and localStorage data in browser fallback profiles.

Deleting only seal.db does not remove model-key ciphertext, Chromium preferences, recovery copies, or browser-fallback data.

Backup boundary

Keep an independent backup outside both application-data directories and test that it can be restored. Close all processes using SQLite before copying it. Backup and migration checks reduce risk in covered scenarios, but failures remain possible. SEAL is a single-machine research notebook, not a regulated collaborative record system.
