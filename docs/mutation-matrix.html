What agents can change

This guide covers source and direct-edition tools. These tools are not bundled with the first Store release. Compare editions.

This is the surface an external agent can read and mutate. External MCP and Rust CLI writes go directly into SQLite. SEAL does not add an approval queue; it makes those writes observable through writeSource, Activity, provenance metadata, checkpoints where recoverable, and live UI sync.

Activity contract

Each canonical external mutation should record:

  • writeSource: mcp or cli
  • command or tool name in metadata
  • target project, conversation, or block ID in structured metadata
  • target block ID when there is one
  • affected project, conversation, and block IDs in structured metadata
  • completed or failed status
  • checkpoint ID before destructive block mutation when the existing schema can keep that checkpoint alive

Collapsed Activity text uses human names and source labels. Raw IDs belong in metadata, JSON, and debug exports.

Conversation-scoped rows live in workflow_events. Workspace, project, and conversation-level rows that must survive conversation deletion live in the durable workspace_events table and appear through the Activity filter labeled Workspace / agent writes.

"Not recoverable in current schema" means there is no restore path today, not that the write is silent. The deletion still records affected IDs in Activity before the rows cascade away. To work against a disposable copy, set SEAL_DB_PATH to a scratch file. See the agent control plane.

Read access

Beyond the mutations above, agents read the same workspace through the MCP tools and CLI query commands. For the full set of operations an agent can call, see the MCP tool reference and the CLI reference.
