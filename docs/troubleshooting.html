Troubleshooting

This guide includes source and direct-edition features. Check the edition comparison for the first Store release. Compare editions.

Fix the problems that come up when you connect an agent, launch the app, or run the CLI. Start by checking the active database path and required dependencies.

An MCP client will not connect

Check the source runtime and client configuration in this order:

  • The server requires a SEAL source checkout. Run npm ci, then configure the client with the checkout's absolute node_modules/.bin/tsx and mcp/server.ts paths. Avoid npx so startup cannot resolve or download an unpinned package.
  • The path in the client's args must point at your checkout's mcp/server.ts. Replace the placeholder path with your own absolute path.
  • Confirm the server starts on its own. Run it from a terminal and read the startup lines, which print to stderr.
cd /path/to/seal
./node_modules/.bin/tsx /absolute/path/to/seal/mcp/server.ts

It prints the database path, the version, and the tool count. If that works but the client still does not connect, the problem is in the client config, not the server.

Restart the client after editing its MCP config. Most clients read the config once at startup, so an edited config does not take effect until the next launch.

An agent writes, but the app does not show it

Compare the database path in Agent Setup with SEAL_DB_PATH in your client configuration.

A client launched from the SEAL checkout resolves to a repo-local .seal/seal.db, while the installed app reads the application-data database. Set SEAL_DB_PATH in the client's env block to the exact path copied from Agent Setup. The default installed-app path is:

~/Library/Application Support/io.github.jvogan.seal/seal.db

Writes reach the app through a file watcher that debounces at 300 ms, so allow a moment after a write before the UI updates. For the full path resolution order, see MCP setup.

An agent reports an empty workspace

Ask the agent to call block_list to read sequence blocks across shared projects and entries. workspace_list reads only MCP Scratch. If block_list is also empty, compare the active database paths.

Run Agent Doctor

In SEAL, run Agent Doctor from Agent Setup or the command palette. It reports the state that connection problems depend on:

  • the active database path,
  • the file watcher,
  • the schema version,
  • Activity hydration.

A missing database path blocks setup. No recent external write is expected until the first MCP write.

Find runtime diagnostics

SEAL does not write a separate log file. To see what a surface is doing:

  • MCP server. It logs to stderr. Run the checkout-local node_modules/.bin/tsx with the absolute mcp/server.ts path to inspect startup logs, database path, and tool count.
  • Activity. Activity records each desktop or agent write with its source. Read it in the app to see what changed and to restore from a checkpoint.
  • Workspace state. The SQLite workspace and Electron profile use separate directories. Check data locations, and close SEAL and every agent process using the database before copying it.
~/Library/Application Support/io.github.jvogan.seal/

The app will not open on first launch

The local unsigned package has no Developer ID signature or notarization ticket, so macOS can block its first launch. Open the installed app once. Then open System Settings → Privacy & Security, select Open Anyway, and confirm Open. See Install SEAL for download and checksum instructions.

The CLI reports "Library not initialized"

The seal lib commands read a local library that you create first. Run seal lib init in your project, then add or import sequences. The seal CLI is a separate binary you build from source; see the CLI reference. The lib library is a folder of files, separate from the SQLite workspace the app and MCP server share.

Contact support

If the problem continues, contact SEAL Support with your SEAL version, macOS version, and steps to reproduce it.
