Connect Gemini CLI

This guide covers source and direct-edition tools. These tools are not bundled with the first Store release. Compare editions.

Add the SEAL MCP server to Gemini CLI so it reads and writes the same on-device workspace you use by hand. Activity records each agent write.

MCP is optional. To install the app with an agent, start with Install SEAL.

Prerequisites

  • SEAL installed and run at least once, so the workspace database exists. See Install SEAL.
  • Gemini CLI installed, with MCP server support enabled.
  • A SEAL source checkout from a repository you have access to. Use the Node.js version in .nvmrc, run npm ci, and use the checkout's absolute node_modules/.bin/tsx path.
  • The path to the SEAL checkout and the path to the database you want the agent to share. The Agent Setup panel in SEAL can copy a ready-to-paste config snippet with the resolved database path filled in.

Configure

Register the server with Gemini CLI's mcp add command, choosing a scope with -s: project (the default, a .gemini/settings.json in the project root) or user (~/.gemini/settings.json, available in every project). Set SEAL_DB_PATH to the database the running app uses, and replace the checkout and database placeholders with your paths.

gemini mcp add seal-bio /absolute/path/to/seal/node_modules/.bin/tsx /absolute/path/to/seal/mcp/server.ts \
  -s user \
  -e SEAL_DB_PATH="/absolute/path/to/active/seal.db"

The command writes a seal-bio entry under mcpServers in the settings file for that scope. To add or edit it by hand, the file uses this shape:

{
  "mcpServers": {
    "seal-bio": {
      "command": "/absolute/path/to/seal/node_modules/.bin/tsx",
      "args": ["/absolute/path/to/seal/mcp/server.ts"],
      "env": {
        "SEAL_DB_PATH": "/absolute/path/to/active/seal.db"
      }
    }
  }
}

Set SEAL_DB_PATH to the same path the running native app uses, so Gemini CLI writes are visible in the UI. Without it, an out-of-process agent can resolve to a repo-local .seal/seal.db while the installed app reads the application-data database, and the two will not see each other's data. See MCP setup for the full path resolution order.

Verify

Confirm the connection before asking the agent to write.

  1. In SEAL, run Agent Doctor from Agent Setup or the command palette. It checks the active database path, the file watcher, the schema, and Activity hydration.
  2. Start a Gemini CLI session and ask it to list your sequences. Gemini CLI calls block_list to read blocks across shared projects and Entries. workspace_list covers only MCP Scratch records.

If the call succeeds, the tools are available. For the full set of tools Gemini CLI can call, see the MCP tool reference. If the UI does not reflect a later write, the usual cause is a database path mismatch; see MCP setup.

Starter prompts

Start read-only, then move to writes once the agent has named its targets. Paste this safety prompt at the start of a session:

You are working with SEAL through the configured SEAL MCP server or Rust seal CLI.

Use the active SQLite workspace only. Start read-only: list sequences, projects, user-facing Entries, and recent Activity if available. The MCP API calls Entries conversations. Then propose a short plan before writing.

Do not delete, overwrite, rename, reorder, or mutate existing blocks unless I explicitly confirm the target and action. Before destructive edits, create or identify a checkpoint. After every write, summarize the affected block names, IDs when available, write source, and any warnings I should verify in SEAL Activity.

Then ask for a read-only inventory:

Use SEAL MCP/CLI read-only tools to inventory my current workspace. List sequences, projects, Entries, feature counts, topology, synthetic-fixture provenance, and any obvious metadata gaps. Do not write yet. End with the next safest actions.

For more copyable prompts and the review patterns that keep agent edits recoverable, see prompts and safety. For how this connection fits the wider system, see the agent control plane.
