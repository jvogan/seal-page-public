Privacy policy

How SEAL stores and sends data.

SEAL keeps your sequences, lab notes, and workspace history on your Mac. It contains no analytics, no telemetry, and no crash reporting. Data leaves your Mac only when you run a tool that contacts a service, and the page below lists every one of them.

Effective 10 September 2026.

Summary

  • SEAL stores your work in a SQLite database on your Mac. No account is required and nothing is uploaded to run the app.
  • SEAL collects no usage analytics, sends no telemetry, and files no crash reports.
  • SEAL does not check for updates on its own. The Mac App Store delivers updates for the Mac App Store edition.
  • Record lookups and protein predictions send data only when you start them, and only to the service that answers them.
  • The Mac App Store edition contacts no AI provider at all and stores no provider key.
  • SEAL operates no workspace server. You control your local files; services you submit data to handle their own copies.

Mac App Store edition

The Mac App Store edition runs inside Apple's App Sandbox. It can open and save files you pick in a standard macOS file dialog, and it remembers those choices so it can reopen the same folder later. It cannot read the rest of your disk.

This edition contacts no AI provider. It cannot store a provider key, and the code that would send a hosted model request refuses to run without that storage, so no sequence or prompt of yours reaches an AI service from it.

It also ships without a terminal and launches no external programs. Alignment executables, genome tools, and scoring runtimes are not installed or run by it. See Edition differences for the full comparison.

Direct-download edition

The direct-download edition can use a hosted protein model. You enter your own API key from the provider, and SEAL sends requests only to the endpoint that key belongs to. Nothing is sent until you run the feature, and no request is sent at all while no key is stored.

This edition also includes a terminal. The terminal runs programs that you install on your Mac yourself, including alignment, genome, and scoring tools or an AI agent command-line tool. Those programs can read files they have permission to access and open their own network connections using credentials you gave them. Their handling of that data follows their own privacy terms.

The contact address on EMBL-EBI requests

EMBL-EBI requires a contact address on every job it accepts. The first time you run an EMBL-EBI analysis, SEAL asks you for an email address and tells you what each submission sends. SEAL stores that address on your Mac, sends it to EMBL-EBI with each job you submit, and never substitutes an address of its own. You can change or remove it in Settings. SEAL never reads your Mac account, your mail app, or your workspace to find one, and no SEAL server receives it.

Removing the address or deleting a workspace does not delete jobs already submitted to EMBL-EBI. Its Job Dispatcher privacy notice describes retention and how to make a data request. Services also receive ordinary connection information, including your IP address.

NCBI lookups work the other way. A contact address is optional there, SEAL substitutes none of its own, and no screen in SEAL asks you for one, so an NCBI request carries no email address at all.

The Mac App Store edition has no terminal and launches no external tool. In an edition that has one, a command-line tool you start receives the prompt and the workspace context you hand it, and sends that on to its own provider under its own privacy terms.

AI provider keys

The Mac App Store edition stores no provider key. Key storage is switched off in it, and every code path that would read or send a key checks that switch first and stops.

In the direct-download edition, the hosted model feature uses your own API key from the provider. You enter the key in Settings, and SEAL encrypts it with the macOS Keychain and writes only the encrypted form to a small file in the app's data folder. The key never goes into your workspace database and never appears in a workspace backup or an export.

SEAL accepts a key only under the fixed identifiers it defines for its own model settings, and rejects any other identifier, so no other secret can be written through the same path.

Delete a key in Settings and SEAL removes the stored ciphertext. Revoke the key at the provider as well if you no longer want it used.

What SEAL does not do

  • No analytics, and no usage or event reporting of any kind. The Usage panel in Settings counts records already in your own database and sends nothing.
  • No crash reporting, in either edition. SEAL registers no crash reporter and uploads no stack traces, logs, or diagnostic reports.
  • No advertising, no advertising identifiers, and no data sold or shared with data brokers.
  • No accounts, sign-in, or profile. SEAL asks for no name or payment detail. The one email address it asks for is the contact address EMBL-EBI requires, and it stays on your Mac except when you submit an EMBL-EBI job.
  • No background network activity. SEAL does not contact a server at launch, on a timer, or to check for a new version.

Keeping and deleting your data

SEAL keeps your data until you delete it. Activity records workspace changes locally, and checkpoints and backups hold earlier versions so you can recover them.

Settings → Data → Clear all data writes a recovery backup, clears the active workspace database, and keeps up to five recovery copies. Delete those copies as well when you want the earlier data gone.

To remove everything SEAL holds, quit SEAL and any tool using the same workspace, then delete the workspace folders you selected, the app's own data folder, and any backups you exported. Deleting seal.db alone leaves the profile and the recovery copies in place.

Deleting the app alone does not ensure its stored data is removed. Check its local data folder, workspace folders, and backups separately.

A stored provider key and your folder permissions are tied to your Mac and your macOS account. Neither is included in a portable workspace backup.

Children

SEAL is a laboratory tool for researchers and students. It is not directed at children under 13.

This website and the support mailbox

This site serves its scripts, styles, images, and recordings from its own address. It loads no third-party fonts, scripts, or trackers, and it runs no analytics. It stores your chosen theme in your browser's local storage, and nothing else.

The site is hosted on GitHub Pages. GitHub logs visitors' IP addresses for security purposes. See GitHub Pages data collection and the GitHub Privacy Statement.

Email sent to support arrives in a Gmail inbox and is used to answer your message. Gmail processes it under Google's Privacy Policy. Support messages are kept while the question is open and deleted on request. Leave private sequences, passwords, and access tokens out of what you send.

Changes to this policy

When this policy changes, the new version appears on this page with a new effective date. A change that affects what SEAL sends or stores will also be described in the release notes for the version that makes the change. Keep using SEAL after a change and the new policy applies.
