Agents · Codex

Run Codex against your local workspace.

Connect Codex to the workspace you use in SEAL. Open the app first, then use Agent Setup to configure this optional MCP connection.

  1. 1. Install SEAL and open the app.

    Install SEAL from source or an available DMG. Open the app to create its local workspace.

    Install SEAL

  2. 2. Run Agent Doctor.

    From the Start Panel choose Agent Setup → Agent Doctor. Doctor verifies the active database path, watcher health, schema version, and Activity hydration.

  3. 3. Get the MCP server source.

    Use your SEAL source checkout, or clone the repository you have access to. Select the Node.js version in .nvmrc, then install the dependencies:

    cd /absolute/path/to/seal
npm ci

    npm ci installs the lockfile-pinned tsx binary used by the local MCP configuration.

  4. 4. Paste this MCP config into Codex.

    The config goes in ~/.codex/config.toml. Codex uses TOML, not the JSON shape used by Claude Code and Gemini CLI.

    [mcp_servers.seal-bio]
command = "/absolute/path/to/seal/node_modules/.bin/tsx"
args = ["/absolute/path/to/seal/mcp/server.ts"]

[mcp_servers.seal-bio.env]
SEAL_DB_PATH = "/absolute/path/to/active/seal.db"

    Replace /absolute/path/to/seal with your checkout path. Replace /absolute/path/to/active/seal.db with the active database path from Agent Setup. The app can copy a configuration with that path filled in.

  5. 5. Verify the connection without writing.

    In a project directory with the MCP server configured, open Codex and ask:

    Use block_list to list the sequence blocks in my SEAL workspace, with type and length. Do not change any data.

    block_list reads blocks across your shared projects and Entries. workspace_list lists only MCP Scratch records. Compare the results with the app before requesting a write.

Try these prompts

Five prompts that exercise the control plane.

Inspect 
show every feature on the SEAL Synthetic Cloning Backbone, including its illustrative status and provenance
Analyse 
find all open reading frames in SEAL Synthetic Genomic Region (30 kb) that are at least 300 bp long, on both strands
Design 
design an in-silico Gibson primer plan for the synthetic reporter and SEAL Synthetic Gibson Backbone, with 20 bp homology and Tm=60
Mutate 
propose one synonymous change in Synthetic Reporter DNA, save a checkpoint first, and record any accepted result as a derived block
Handoff 
export the current Entry as a review-preset package with GenBank, FASTA, manifest, and validation

Verify

Three ways to confirm Codex is wired up.

Agent Doctor green

Doctor reports the database path, watcher, schema version, Activity hydration, and recent external writes. Run it again after configuration changes or a failed connection.

Activity row tagged with the source

Every external mutation records its canonical source. Codex normally writes through MCP; a Codex client label appears only when provider tagging is supplied and accepted.

Checkpoint diff before and after

Take a checkpoint, let Codex run, take another. The diff between checkpoints shows exactly what changed and lets you accept or roll back.
